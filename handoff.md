# Передача работы на Windows — 24.09.2026

## Где продолжать

Репозиторий: `https://github.com/lehjke/tflex-backend-service.git`. Текущая ветка на Mac — `main`, HEAD — `bfe04e6` (`design changes`). На момент записи **не закоммичены** только два файла:

- `src/TFlexDrawingService.Api/wwwroot/pricing.html`
- `src/TFlexDrawingService.Api/wwwroot/pricing.js`

Этот `handoff.md` тоже новый локальный файл. Обычный `git clone` на Windows не принесёт ни его, ни две правки. Скопируйте эти три файла в checkout того же коммита. Не заменяйте Windows checkout без проверки его собственных локальных изменений (`git status`).

## Последний запрос и текущее решение

Пользователь показал два замечания к форме цены XIZI: в выпадающем списке поручней оставить только количество; убрать два поля, задающих тип дверей. Сделано в рабочем дереве:

1. Поле «Поручень, положение» переименовано в «Количество поручней». Варианты на экране — `0`, `1`, `2`, `3`. Их внутренние значения остались прежними (`Нет`, `1 х Задняя стена`, `2 х Боковые стены`, `3 х Все стены`), чтобы не менять расчёт, сохранённые спецификации и заводской экспорт.
2. Видимое поле «Тип дверей» скрыто. «Тип открывания дверей» осталось единственным выбором пользователя. Скрытый `doorTypeSelect` сохраняется в DOM: существующая функция `syncXiziPricingFields()` выводит из него `CO` или `2S`, а расчёт и сохранение продолжают использовать это значение.
3. Обновлён query-параметр скрипта `pricing.js` в `pricing.html`, чтобы браузер получил свежую версию.

Если на Windows доступен только чистый `bfe04e6`, эти изменения можно восстановить по текущему diff на Mac (`git diff -- src/TFlexDrawingService.Api/wwwroot/pricing.html src/TFlexDrawingService.Api/wwwroot/pricing.js`). Не подменяйте исходные значения опций поручня числами: это изменит данные, уходящие в расчёт/экспорт.

Проверено на Mac: в браузере у XIZI отображаются `0–3`, второе поле типа дверей скрыто; при выборе телескопического открывания скрытый тип становится `2S`. `node --check` прошёл, 19 целевых frontend-тестов прошли, `git diff --check` прошёл. Изменения **не проверялись на Windows** и не коммитились.

## Запуск на Windows для продолжения UI-работы

Нужны .NET SDK 10 и Node.js 22 (версии Windows CI в `.github/workflows/ci.yml`). В PowerShell из корня репозитория:

```powershell
$env:DOTNET_ENVIRONMENT = 'Development'
$env:ASPNETCORE_ENVIRONMENT = 'Development'
dotnet run --project .\src\TFlexDrawingService.Api
```

Открыть `http://localhost:5011/pricing`. Development-конфигурация API отключает аутентификацию. Для правок формы цен Worker не требуется. Если понадобятся задания генерации чертежей, в отдельном PowerShell запустить Worker с `$env:DOTNET_ENVIRONMENT = 'Development'` и `dotnet run --project .\src\TFlexDrawingService.Worker`; в этом режиме используется Mock вместо T-FLEX.

Проверка после переноса:

```powershell
git status --short --branch
node --check .\src\TFlexDrawingService.Api\wwwroot\pricing.js
node --test .\tests\frontend\*.test.mjs
dotnet test .\tests\TFlexDrawingService.Tests\TFlexDrawingService.Tests.csproj
git diff --check
```

Отдельно проверить в браузере XIZI: количество поручней `0–3`, видим только «Тип открывания дверей», переключение центрального/телескопического открывания, сохранение и повторное открытие спецификации. Последние два действия после этой правки вручную ещё не проверялись.

## Контекст проекта

Это ASP.NET Core API со встроенным интерфейсом в `src/TFlexDrawingService.Api/wwwroot`; нет отдельной frontend-сборки. В предыдущей работе добавлены проектные заводские выгрузки XIZI/SMEC, окно проекта в личном кабинете, изменения бокового меню и формы цены. Текущая правка намеренно касается только отображения двух полей XIZI; логика цен, файлы экспорта и SMEC не менялись.

В переписке ранее сравнивали итог XIZI старого калькулятора `175 608,24 CNY` с новым `169 308,24 CNY` (разница `6 300 CNY`). Не считайте эту разницу устранённой только по текущим UI-проверкам: если возвращаться к паритету расчёта, заново воспроизведите конкретную конфигурацию. Основные документы: `README.md`, `docs/xizi-pricing.md`; production-установка Windows Server описана отдельно в `docs/server-bootstrap.md` и не нужна для локальной проверки формы.
